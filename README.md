# 语文试卷AI批改系统

教师上传参考答案和学生试卷扫描件，系统把每份试卷的所有页面连同参考答案打包，
调用教师自己配置的多模态大模型完成批改，并给出班级学情分析。

程序本身不做 OCR、不做切题、不做评分规则引擎。**评分规则全部写在提示词里**
（[backend/app/services/prompts.py](backend/app/services/prompts.py)），
要调整评分尺度改那一个文件即可，规则来源见
[语文试卷AI批改工作流与评分规范_V1.0.md](./语文试卷AI批改工作流与评分规范_V1.0.md)。

## 快速开始

双击根目录的 **`start.bat`**，它会自动创建虚拟环境、安装依赖、生成配置文件，
并在两个窗口分别启动前后端，最后打开浏览器。关闭对应窗口即停止服务。

首次使用需要在网页的**模型配置**页填写你自己的 API Key。
目前预置了 DeepSeek、豆包、千问，也可填任意 OpenAI 兼容接口。

> **必须用支持视觉的模型。** DeepSeek 只有 `deepseek-flash` 支持读图，
> `deepseek-v4-pro` 不支持（[官方文档](https://api-docs.deepseek.com/guides/vision)）。

## 使用流程

```
①模型配置：粘贴 API Key
        ↓
②考试管理：上传参考答案（Word / PDF / 文本 / 图片）
        ↓
③两种批改方式二选一
   · 批改试卷——先建学生名单，再逐人上传，适合正式考试
   · 批量导入——先把一摞扫描件全传进来，拖拽合并多页，事后再对姓名，适合小测验
        ↓
④批量批改 → 逐题查看、人工改分
        ↓
⑤成绩统计：分数分布、逐题得分率、AI学情分析与教学建议
```

## 功能

| 模块 | 说明 |
|---|---|
| 模型配置 | 选厂商自动填地址和模型名，粘贴 Key，可测试连接；思考模式开关与强度选择 |
| 考试管理 | 上传参考答案；**逐题参考答案可直接编辑**，改后作为权威答案参与后续批改 |
| 学生管理 | 班级增删、粘贴名单批量录入学生 |
| 批改试卷 | 按学生组织，逐人上传（可多页），一键批量批改 |
| 批量导入 | 图片/PDF 批量导入，**拖拽卡片合并**成多页试卷，多页可**拆分**，学生姓名可后补 |
| 批改结果 | 逐题得分与扣分原因、作文评价、待复核标记，对照原卷查看，**逐题和作文均可人工改分** |
| 成绩统计 | 分数分布、逐题得分率、失分原因汇总；一键生成**学情分析与教学建议** |

支持的上传格式：参考答案 `.docx / .pdf / .txt / .md / 图片`，学生试卷 `图片 / .pdf`。

## 识别模式

试卷扫描件通常远超模型的图片像素上限（DeepSeek 约 130 万像素），整页发送会被压缩。
以 4491×3173 的扫描件为例会被缩到 34%，原本 30 像素高的拼音只剩 10 像素，
括号里的读音、被圈或划掉的小字就糊了。

- **普通模式**（默认）：整页发送，快且省，适合字大、作答清楚的简单测验。
- **高清识别模式**：按像素上限把每页切成小块（该扫描件切成 12 块），每块都不被压缩，
  清晰度约提升 3 倍；相邻块留 8% 重叠，避免记号正好压在切割线上。
  代价是每份试卷多约 0.03 元、速度略慢。

在「批改试卷」「批量导入」页的工具栏上随时切换。

## 成本

以 deepseek-flash、一份 2 页试卷为例（实测数据）：

| | 思考模式 | 关闭思考 |
|---|---|---|
| 耗时 | 约 70 秒 | 约 13 秒 |
| 输出 token | 约 16,000（其中思考约 13,000） | 约 2,600 |

成本大头是输出的思考 token，一个 30 人班级约 2~3 元。参考答案部分依靠
DeepSeek 的前缀缓存复用（命中价格为未命中的 1/50），所以提示词里
**不能掺入学生姓名等因人而异的内容**，否则每份都缓存未命中。

## 目录结构

```
backend/          FastAPI + SQLite
  app/services/
    prompts.py      评分规则与输出格式（要调评分尺度改这里）
    workflow.py     批改编排：打包图片 → 调模型 → 汇总分数
    model_provider.py  统一的多模态调用层（OpenAI 兼容协议）
    image_utils.py  高清模式的页面切块
    pdf_utils.py    PDF 取文字 / 渲染成图片
    statistics.py   成绩统计（纯计算，不调模型）
frontend/         React + TypeScript + Ant Design
scripts/          start.bat 调用的前后端启动脚本
resource/         教师本地的试卷与答案（不进版本库）
```

## 几个实现上的注意点

- **总分由程序汇总，不采信模型自报的数字**。实测关闭思考模式时模型求和会出错
  （逐题合计 89 却报 82），因此总分和各大题小计一律按逐题分数相加。
- **逐题统计按题目位置对齐，不按题号**。模型给出的题号写法并不稳定，同一道题可能
  写成"二、1"或"二、选择题1"；题数与多数人不符的试卷会被排除并在页面上注明。
- **及格率以试卷实际满分为分母**。建考试时总分常留着默认的 100，而小测验实际可能
  只有 21 分，按配置值算会得出"及格率 0%"的误导结论，不一致时页面会提示。
- **批处理文件必须是 CRLF 换行 + GBK 编码**。LF 换行会让 `set` 赋值静默失效，
  脚本行为异常却不报错；`.gitattributes` 已固定换行符。
- 数据库新增字段由启动时的 `ensure_columns()` 自动补上，不会丢已有批改数据。

## 数据与隐私

- API Key 加密后存在本地数据库，`.env` 与 `*.db` 均已在 `.gitignore` 中。
- 学生试卷扫描件存放在 `backend/storage/`，参考答案与扫描件放在 `resource/`，
  两者都不进版本库。
- 整个项目在本地运行，除调用你配置的模型接口外不向任何第三方发送数据。
